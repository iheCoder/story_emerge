# Story Spine：固定的全书演进路线

Story Spine 用简短路线说明全书从什么处境走向什么处境。它帮助 Director 将局部发展与全书承诺联系起来；具体章节仍由 Writer 创作。路线文案更清楚，不等于已经证明连续正文或整部小说更好。

## Architect 生成什么

`story_spine` 是按发展顺序排列的字符串数组。每项用一句话描述整个故事核心处境或其主要转向，各项共同覆盖开场到承诺兑现的路线。

旧版 `from / to / why_it_matters / exit_evidence` 已删除。把人物、关系、社区分别写成从开端到终局的变化，会产生几条并行弧线；给它们补充原因和成立证据，也不能自动得到全书的发展顺序。现在直接生成所需的路线，不再先生成这些中间字段。

路线依据完整 Core，各部分承担不同作用：

| 内容 | 用途 |
|---|---|
| story_engine.loop | 局面与人物回应怎样持续产生后续故事 |
| story_engine.progression_axis | 这些循环长期累积的变化方向 |
| reader_promises[].promise | 读者期待的核心收获 |
| reader_promises[].payoff_shape | 收获通过怎样的经历、选择或结果呈现 |
| experience_contract | 持续阅读的感受、形成感受的叙述方式，以及不能偏离的作品身份 |

提示词在使用这些字段时直接解释其用途，不假定模型读过项目讨论。路线不分别复述每条承诺，不把同一变化反复拆成“更加深入”的几项，也不提前规定具体事件、线索或解决手段。用户已经指定的内容仍优先。

后来的发展承接此前影响，允许重叠和交织，不要求严格的一因一果或每项都永久改变世界。安静日常同样可以形成路线，不强求成长、大冲突或封闭答案。

目标篇幅影响路线划分的粗细，不影响单项详细度。跨度过大时保留必要的中间转向；节点数量由故事决定，没有固定数量、字数换算公式或每项长度校验器。

## Director 如何使用

Director 先依据正式历史判断当前处境，再对照路线理解长期发展，最后判断当前 Direction 是否仍值得展开。输入包含当前状态、最近五章轨迹、全部章节摘要与最近两章正式正文。

路线是规划参照，不能充当事实。解释有缺口不等于其他解释已被排除，局部表现也不等于长期关系已经形成。正文可帮助核对摘要省略的限制和反证；更早细节不可见时，不能声称已核验全书原文。

Direction 继续只用四个字段：

| 字段 | 用途 |
|---|---|
| current_position | 依据历史说明当前处境及相关变化实际形成的程度 |
| focus | 未来若干章主要关注哪片已有的关系、处境或问题 |
| desired_shift | 在这个区域内，值得逐渐形成什么变化 |
| reader_expectation | 读者基于已读内容会持续关心什么尚待回应 |

`current_position` 不携带未来节点或终局预告，也不覆盖正式事实与人物知情范围。阅读期待可以是相处、陪伴和体验延续，不必制造新秘密。

KEEP 原样保留全部四字段；ADJUST 修正仍然有效的方向，包括会误导 Writer 的位置判断；REPLACE 选择自然接续的发展重心。动作针对 Direction，不代表 Spine 通关。没有阶段游标、完成比例、逐节点任务或额外评分角色。

熟悉的活动仍可积累关系、情绪和日常价值。方向可以深入同一个转向，也可以承接多个转向的重叠部分，不能为了路线倒退关系、强造误会或跳过必要过程。正式历史与路线难以衔接时，Director 在 `reason` 简述不匹配，依据历史和 Core 选择当前方向，不另写全书路线。

## 固定参照与篇幅边界

Architect 的路线随初始 checkpoint 保存，之后只读。Director 仍只输出 `action`、`direction`、`reason`；后者仅供审计，不传给 Writer。普通章节提交、方向复查和重启都保留原始路线。

完整 Spine 不进入 Writer 或 Editor。Commit 可读取 Spine，结合 Direction 和近期轨迹筛选仍需保留的当前状态，但不能把路线中的未来变化写成已成立事实，也不能修改 Spine 或 Direction。Editor 不以单章是否完成路线转向验收正文，全书完结仍由 Editor 对 ACCEPT 正文的判断确认。

Director 或 checkpoint 写入失败时，已提交章不回滚，旧 Direction 保持正式有效；下一次 Run 先重试复查，再写下一章。审计文件不代表提交成功。

篇幅是质量优先的软目标。优先减少可选支线和重复证明，同时保留人物反应、关系积累、过渡、后果及余韵。合并节点不等于完成铺垫，不按字数比例推进阶段，也不为凑下限延长已自然落地的故事。

## 验证与数据格式

工程测试覆盖字符串路线初始化、空值及旧对象格式拒绝、三个 Direction 动作保留路线、重启恢复、下游输入隔离和提交故障。校验只约束数据与权限，不将文学判断编码为规则。

本轮真实模型请求、原始输出与语义观察见 [提示词实验报告](../eval/spine-prompt-20260906/REPORT.md)。实验使用项目实际配置的模型，不能据此声称已经验证 GPT-6 或整部小说质量。

旧项目缺少 `story_spine`、缺少 `current_position`，或仍使用四字段对象数组时，不做自动迁移。旧对象之间未必存在全书顺序，机械拼接成字符串会伪造路线。本版用于新建作品，旧产物保留为历史材料。
