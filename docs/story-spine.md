# Story Spine：固定的全书变化参照

本版增加长期变化参照，让 Director 判断前面建立的内容正在怎样支持后续故事。设计目标是增强整体因果与阶段演化，同时保留章节自身的生活感、情绪和创作空间；文学质量收益尚未经过新作品对照验证。

## 提示词的核心选择

Architect 先从 Core 的发动机、长期变化维度、承诺和体验约定出发，用相同变量比较起点与终点，再寻找当前路径中的关键变化。避免先列“相遇、暧昧、冲突、分离、告白”等标签，再给标签补因果。

Spine 只使用四个自然语言字段：

| 字段 | 表达什么 |
|---|---|
| from / to | 同一关键关系、认知、选择方式或处境在变化前后的差异 |
| why_it_matters | 这项变化如何为后续提供条件、后果或意义 |
| exit_evidence | 哪些实际表现能够支持变化成立，哪些较弱表现还不足以支撑它 |

例如“人物愿意就某个私人困境求助”可以支持局部信任，但不能直接推出“已经默认让对方参与重要决定”。exit_evidence 描述这种可辨别的差异，不写“已经充分建立”之类自我循环的结论，也不规定互动次数、章节数或唯一证明事件。

用户要求和 Core 承诺约束最终需要兑现什么；Architect 应将参照建立在关键变化和因果依赖上，保留具体实现的空间。两个角色可以在压力下共同应对，不能预设必须先疏远再和好。也不强迫所有故事最终出现成长、关系升级、大冲突或封闭答案。

删除、交换、多实现检查仅作为 Architect 的内部思考：删掉变化会损失什么，先后是否有真实依赖，实现能否保持开放。并行变化允许换序；用户指定的事件不因实现唯一被删除。没有固定阶段数量或额外评分角色。

## Director 如何使用

Director 每次先读真实历史，再对照 Spine，判断哪些变化已成立到什么程度、尚缺什么支撑、哪些前章后果还没被人物消化。输入包含当前事实、最近五章轨迹、全部 Ledger 和最近两章正式正文。原文保留摘要容易省略的情绪、范围限制和反证；更早原文没有进入输入，不能声称已核验不可见细节。

Direction 增加 current_position，将这份有证据范围的判断传给 Writer。它不能覆盖世界事实、人物认知或上一章正文，也不携带完整 Spine、未来阶段列表和终局预告。

当前位置不意味着活动禁令。信任已经成立后，一顿饭、一次照顾仍可以表现新的关系含义、形成熟悉感或承接余波。阶段可以重叠；新方向必须从已有处境、压力和后果中接续，不能只复制 Spine 的下一个终点。

Direction 仍用 KEEP / ADJUST / REPLACE。只需要纠正会误导 Writer 的 current_position 时可以 ADJUST；有了新证据却没有改变方向的必要时保持 KEEP。动作针对当前方向，不代表 Spine 阶段通关。没有阶段游标、完成百分比、强制 ADVANCE 或逐级移动规则。

## 避免字段职责重叠

Director 提示词先区分各份输入回答的问题，再按“历史证据 → 长期变化的因果位置 → 当前方向是否仍值得发展”作判断。没有增加评分表、阶段状态或额外输出。

| 内容 | 回答的问题 |
|---|---|
| story_engine.loop | 故事局面如何持续产生 |
| progression_axis | 这些循环长期积累在哪个变化维度上 |
| reader_promises[].promise | 承诺给读者什么核心收获 |
| reader_promises[].payoff_shape | 通过怎样的经历、选择或现实结果，才算呈现了这份收获 |
| Spine | 关键变化之间有什么因果支撑，实际历史是否已建立这些变化 |
| experience_contract | 应持续带来什么体验、通常怎样讲述、哪些发展会改变作品身份 |

例如 promise 可以是“看见两个孤独的人获得可依靠的关系”，payoff_shape 则说明“这种依靠在自主选择和实际承担中可见，而不止于表达好感”。两者同属一个承诺，后者补充兑现方式，不是第二个同义目标，也不预定某次救援或告白。Spine 的 exit_evidence 则用于判断其中某项关键变化是否成立，不要求它与某个承诺逐一对应。

Direction 四字段也有不同用途：current_position 提供位置依据，focus 选择关注区域，desired_shift 表达故事中的变化意图，reader_expectation 表达读者当前关心的未回应之处。最后一项不把期望变化简单改成问句，也不重列全书承诺。对日常与陪伴的期待同样成立，无需新造谜团。

## 固定参照与持久化

Architect 的 `story_spine` 随第0章 checkpoint 保存，后续只读。Director 只输出 `action`、`direction`、`reason`，没有 Spine 修正字段；Schema 与严格解码都拒绝越权字段，状态更新也没有修改 Spine 的分支。

固定的是全书变化参照，对实际进展的判断仍须服从正式历史。尚欠支撑时，Direction 承接已有后果并为相关变化建立条件；不能为了遵从参照倒退关系、强造误会或跳过人物反应。如果事实与参照难以衔接，reason 说明具体不匹配，Direction 仍从事实与 Core 出发支持相关长期变化，不编造阶段完成，也不变成另一套全书路线。

reason 简短说明正式历史中的依据和必要的不确定性，只用于审计，不进入 Writer。普通 Chapter Commit 与 Direction Review 均保留初始化的 Spine；后者只更新当前 Direction、方向版本和最近复查章号。没有独立的 Spine 更新接口或可变全局文件。

Director 或 checkpoint 写入失败时，已提交章不回滚，旧规划整体保持正式有效。下一次 Run 先重试复查，成功后才写下一章。先行写出的审计记录不是生效证明；不能把 `.work` 或审计内容手工拼进状态。

完整 Spine 不传给 Writer、Editor 或 Commit。Editor 仍按章节贡献、序列和执行验收，不因章节没有立刻完成阶段变化而拒绝正文；位置判断过强时，可随 ACCEPT 请求 Director 复查。

## 篇幅服从质量

保留现有软区间与已提交正文字符数。Architect 从源头控制可选支线和承诺的展开复杂度；Director 持续结合尚需兑现的内容考虑收束，不等到超长后才仓促压缩。

没有 Hard Max、单章固定配额或程序化结局。允许必要的铺垫、人物反应、过渡、后果和余韵占用更多空间，也允许在目标下限之前自然结束。减少可选复杂度不等于删除必要条件；合并两个节点也不等于已经完成两个变化。

Writer 初稿和修订均保留这些质量边界，Editor 不把正常篇幅偏离作为拒绝理由。全书完结仍只来自 Editor 对 ACCEPT 正文的确认。

## 验证范围

工程测试覆盖初始化、严格输出、KEEP / ADJUST / REPLACE 均保留初始 Spine、重启与下一轮 Director 读取、下游输入隔离、checkpoint 写入故障及超出软篇幅后的续写。测试使用脚本化模型，验证真实生产链路的权限和状态，不评价提示词的文学效果。

后续作品对照最应观察的语义边界是：局部信任被夸大、重复日常仍有价值、实际发展与固定参照难以衔接、跨阶段过渡与余波、空间不足但必要铺垫尚未完成。应分别读连续正文和完整作品，不用 Spine 文案或阶段完成度代替阅读质量。

旧项目缺少 Spine 或 current_position 时不会自动迁移；本版使用新建作品，保留旧产物作为历史材料。
