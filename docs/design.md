# V1：一座会记账的小说工厂

## 1. 工厂为什么存在

一次提示可以写出漂亮的一章，却很难可靠地背着几十个事实、秘密和承诺走到结局。V1 不试图制造一个无所不能的“作家人格”，而是让普通模型在一个清楚的生产流程里工作。

目标限定为中文类型中篇：约 12～30 章、2～8 万字、少量核心人物、完整结局。它首先要稳定产出像小说的初稿，再谈百万字连载、群像模拟或文学实验。

## 2. 四个主角

总导演决定故事为什么向前走。开书时建立读者承诺、人物、阶段和结局；每章只规划最近一步；每四章重新判断未来方向。

小说家把计划变成场景。它负责动作、对话、节奏和情绪，但不能擅自改变最终真相。

书记员在正文完成后记录状态差量。它区分客观事实和人物知识，只把正文已经证明的事情写进历史。

编辑是提交门卫。它检查事实冲突、知识泄露、人物失真、剧情空转和爽点失效。编辑只给修改指令，由小说家统一修订，避免多个角色同时改坏正文。

终章还有一道程序闸门：所有剧情线必须进入 `resolved`，否则即使单章评分合格也不能把项目视为完成。这是实际跑书后补上的约束——章级质量不能替代全书闭合。

## 3. 一个章节就是一次事务

```text
读取 HEAD
   ↓
构造工作上下文：故事圣经 + 当前状态 + 最近三章摘要 + 上一章正文
   ↓
计划 → 正文 → 状态差量 → 编辑审核
   ↓                    │
   └──── 最多完整修订一次 ←─┘
          二审若仅剩一个局部硬伤，可小修一次并复审
   ↓
写入不可变产物和新检查点
   ↓
原子替换 HEAD
```

旧章节和旧检查点永远不在原地修改。`.work/` 保存未通过的草稿和评审，帮助人类判断到底是 Prompt、模型还是故事本身出了问题。

## 4. 为什么正文不是记忆

系统保存七类信息：故事契约、客观事实、人物当前状态、人物知识、人物关系、剧情线、时间线。下一章仍会看到上一章全文，但它只作为局部语气和接续参考；真正决定“世界现在怎样”的是检查点。人物的目标、情绪和位置按当前值更新，知识和关系按稳定 ID 合并增量，避免后半段重复输出全部历史。

摘要只保存每章发生了什么，不会反复把整个历史重新总结。因此“喝咖啡不加糖”之类明确事实不会在摘要的摘要中逐渐变成模糊性格。

## 5. 动态规划但不随意漂移

总导演提前确定少量故事阶段和结局，不一次写死全部章节。每章规划使用当前状态，每四章复盘未来一小段。这给故事保留变化空间，同时用故事圣经阻止模型为了眼前一章推翻全局。

## 6. V1 有意不做什么

- 不做角色自由模拟。它可能增加涌现感，也会显著增加调用、冲突和调试成本。
- 不做向量检索。中篇的结构化状态和最近上下文足以验证核心闭环。
- 不做知识图谱数据库。人物知识与剧情线已经用普通 JSON 表达。
- 不自动无限重写。一次完整修订后，只有“篇幅合格、二审至少 70 分、仅剩一个硬伤”才允许局部小修；否则停下让问题可见。
- 不用框架隐藏流程。每个阶段都能在 `internal/workflow` 中线性阅读。

## 7. V1 成功标准

1. 能从一个点子持续运行到完整结局。
2. 后半段仍遵守人物知识、世界规则和已提交事实。
3. 主要剧情线被推进和回收，而不是在中途遗忘。
4. 每章都有行动、阻碍、变化和后果，不是长度足够的剧情摘要。
5. 任意阶段中断后可以从最后一次提交恢复。
